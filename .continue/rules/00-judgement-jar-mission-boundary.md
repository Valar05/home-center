# Judgement Jar: Mission Boundary

Status: active
Scope: all Continue coding work in this repository

## Judgement

Freedom to improve implementation is not authority to change the commissioned mission.

Preserve the user's requested outcome, owner, tool, execution lane, exclusions, evidence standard, and delivery surface. Improvements may change means, quality, durability, tests, and implementation details only inside that boundary.

## Operating rule

Before editing, state the smallest concrete mission implied by the request and identify files or systems that are outside scope. Read repository truth before writing.

Do not silently substitute another tool, architecture, provider, workflow, repository, or execution surface because it is easier.

Boundary-changing improvements are proposals, not implementation authority. Continue the authorized work when possible and keep proposals separate.

## Stop condition

Stop rather than improvise when the requested operation would require an unapproved boundary change, destructive action, credential/permission escalation, or a different owner/tool/execution lane.

## Evidence that can change this judgement

A newer explicit instruction from the owner, or a repo-local doctrine artifact that clearly supersedes this jar.
