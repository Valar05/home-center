# Worker Resource Contract

`ops/worker_profiles.v1.json` is the machine authority for worker resources. `control-plane`, `discord-interaction-control`, `media-forge-light`, `media-forge-heavy`, and `browser-session` are the available profiles.

`home-center-mcp` is the general control-plane guardrail. `venice-discord-interactions` is bound to `discord-interaction-control` through `tools/deploy_venice_discord.sh`; its Firebase options module is generated from the registry, validated before deployment, and compared with the underlying Cloud Run service after deployment. The pilot holds exactly one 512 MiB instance warm and caps the service at one total instance so Discord signature verification, exact-route authorization, consent-state transitions, immediate callbacks, and authenticated single-message generation tasks stay inside a disclosed cost envelope. Discord receives a deferred acknowledgment before provider work begins. It runs under the dedicated `venice-discord-runtime@home-center-dclar.iam.gserviceaccount.com` identity, and live readback must reject the broad default compute identity. Deployment is blocked until the owner explicitly approves that ongoing single-instance cloud cost. `home-center-audio-render`, `home-center-video-render`, and `home-center-browser-worker` remain documented targets. `home-center-blender-workspace` is bound to `media-forge-heavy`: 4 vCPU, 8 GiB, concurrency 1, scale zero to four, timeout 1800 seconds. It executes one deterministic Blender operation against one explicit immutable scene revision per instance.

Bound deployments resolve values from the registry, reject ad hoc overrides, validate before mutation, and read back live configuration. The Blender workspace release requires a clean exact `origin/main`, deploys the replacement before removing the retired runtime, and never rolls back to a geometry-authoring fallback.
