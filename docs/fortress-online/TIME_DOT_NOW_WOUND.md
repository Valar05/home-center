## Escalation law

Every unresolved tick escalates. It may never return the same class of answer twice.

`TICK 0 → OBSERVE`
Read authoritative physical/runtime truth.

`TICK 1 → BITE`
Attempt the smallest authorized mutation that attacks the highest-priority wound.

`TICK 2 → CHEW`
If the bite fails, inspect the exact failure and change mechanism, route, test, or implementation. Repeating the same attempt is forbidden unless new evidence justifies it.

`TICK 3 → DIGEST`
Promote the discovered failure class into durable machinery: test, skill, router, recovery rule, jar, or acceptance gate.

`TICK 4 → METABOLIZE`
Use that machinery to make a second external state transition. Documentation alone cannot satisfy this stage.

`TICK 5+ → HYPERBOLIC ESCALATION`
Each subsequent unresolved tick must increase leverage: broader worker fan-out within authorized Git lanes, stronger deterministic recovery, removal of human transport, regression fixture, or physical canary. Escalation must remain bounded by Drew's authority and safety constraints; it cannot invent permissions.

## Digestive progress bar

The UI clock is the mouth of this organism. Its state is not percent complete. It displays the current digestive verb and elapsed wound age:

`OBSERVE → BITE → CHEW → DIGEST → METABOLIZE → ESCALATEⁿ`

A press must be interactive and consequential. It emits haptic feedback immediately, announces the current verb accessibly, records the timestamp, then advances the existing Waltz:

`RECOVER → DELIVER → FARM`

## Scheduling / swarm care

The Waltz does not mean creating arbitrary new scheduled jobs. Existing workers/tasks are the dancers. Each tick inspects their age, last receipt, blocker, and successor; stale workers are rescued, rerouted, or retired through the authorized lane. Scheduling is orchestration state, not worker multiplication.
