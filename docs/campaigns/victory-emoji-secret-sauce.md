# Victory Emoji — Secret Sauce Campaign

## Commission
Produce a native-phone, text-message-sendable VICTORY emoji/GIF lineage that is never static, never boring, and earns its compute budget through visible authored animation quality. The artifact is the animation itself; no adjacent dashboard, poster, daemon, or generic asset substitutes.

## Hard invariants
- STATIC = REJECT.
- BORING = REJECT.
- One-frame exports, fake GIF wrappers, trivial two-frame wiggles, stock emoji animation, and cosmetic transforms over an unchanged drawing are negative fixtures.
- Generation may deliberately use substantial desktop/GPU compute when that compute buys perceptible quality: richer motion synthesis, deformation, secondary motion, procedural anatomy/material behavior, lighting/effect passes, temporal coherence, variant search, compositing, or judging. Expensive-for-expensive's-sake is still waste.
- Final delivery remains compact enough for ordinary phone messaging. Heavy generation is allowed; bloated delivery is not.
- Source/master representation and final messaging artifact remain separate.

## Jar map — mandatory every generation
Every candidate records a complete mapped pass, not an optional cast performance:
- MIRROR: Is this still the commissioned native sendable victory animation?
- EVIDENCE: What proves frame diversity, animation, phone presence, and Messages sendability?
- SCOPE: Kill adjacent products and bolt-ons.
- CONSTRAINT: Preserve native phone + text-message + animated + delightful + compute-justified requirements.
- CONTINUITY: Preserve all prior corrections and rejected failure classes.
- HUNGER: Attack staticness, boredom, generic motion, wasted compute, and fake completion.
- THIRST: Mine existing vector, pixel, motion, Fleshpunk/Flesh Prank, Joy Ledger, and animation machinery before commodity generation.
- HARAWAY/OPERATOR: Drew is not transport, installer, or test harness when an authorized body exists.
- NOODLE QUEEN: Taste gate; reject ugly, illegible, generic, inaccessible, or joyless specimens.
- PUNNETT: Breed variants from surviving motion/style genes; preserve winners and negative fixtures.
- ARES: Escalate spectacle where it improves the tiny artifact; never obscure readability.
- VENICE: adversarial plan/completion review; CONTINUE_REQUIRED until physical commissioned-surface evidence exists.

## Evolution loop
RECOVER SOURCES -> MAP ALL JARS -> BREED COMPUTE-WORTHY VARIANTS -> RENDER -> MEASURE FRAME DIVERSITY/TEMPORAL COHERENCE -> JUDGE -> EXPORT COMPACT GIF/ANIMATED MESSAGING FORM -> INSTALL/EXPOSE ON PRIMARY PHONE -> SEND THROUGH MESSAGES -> RECEIVE/VERIFY -> KEEP/REJECT -> BREED AGAIN.

## Compute justification receipt
Each candidate stores: generation method, source lineage, render duration, approximate compute class, frame count, distinct-frame count, dimensions, file size, motion genes, visual/effect passes, judge results, and why the expensive stages materially improved the artifact. If substantial compute produces no perceptible gain, Hunger kills that stage.

## Acceptance states
REQUESTED -> SOURCE_RECOVERED -> JARS_MAPPED -> MASTER_GENERATED -> ANIMATION_RENDERED -> FRAME_DIVERSITY_PROVEN -> TASTE_PASSED -> PHONE_INSTALLED -> MESSAGES_SENDABLE -> SENT -> RECEIVED -> USER_KEPT.

Never collapse states. Repository existence proves only repository implementation. The campaign does not stop at a good GIF file; it continues until the artifact is genuinely usable from the primary phone in text messages and the lineage can keep breeding better animated victory specimens.
