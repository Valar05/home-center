# Animation Kinship Bridge

Status: OPTIONAL SIBLING-INPUT CONTRACT

ASCII Kinesis may consume **non-authoritative key/timing metadata** from sibling animation systems without containing their runtimes or surrendering UAPL/ASCII authority.

Current bridge schema name:

`ascii-kinesis-kinship-bridge.v1`

The first producer is the deterministic-vector-engine experiment branch `fertile/flat-plane-paper-doll-v1`, which exports the bridge from its native `kinetic-key-contact.v1` ledger.

## What the bridge may carry

- source-system identity;
- source specimen ID;
- source media hash;
- ordered key IDs;
- readable key names;
- kinship/phase roles;
- source frame addresses;
- exact source times;
- explicit hold/exposure frames and seconds;
- timing provenance;
- authored/generated status.

## What the bridge is not

It is not:

- UAPL;
- UAT;
- ASCII pose geometry;
- Motion Dungeon connective motion;
- a `.motion.html` deliverable;
- a command to retime into ONES/TWOS/FOURS;
- permission to import a sibling renderer, paper-doll runtime, Pose Lab runtime, or art provider.

ASCII Kinesis remains responsible for its own authored ASCII keys, evidence boundary, timing opinion, compiled media, three-tab SPA, quality gates, and human delivery.

## Timing law

When a sibling bridge supplies exact source-key spacing with observed provenance, preserve it as evidence.

ASCII Kinesis may later author a derived presentation timing, but it must label the derivation explicitly, for example:

- `DERIVED_UAT_OPINION`
- `DERIVED_ONES_TWOS_FOURS`
- `DERIVED_GAMEPLAY_RETIMER`

Never silently replace exact observed source spacing with `STREET_FIGHTER/CAPCOM` simply because that vocabulary exists.

## Key identity law

If an ASCII study is spawned from a bridge, preserve source key IDs or store a reversible mapping. The point of the bridge is that the flat-plane, Pose Lab, and ASCII contact sheets can discuss the same decisive moments without sharing implementations.

## Validation

Use:

```sh
python3 tools/validate_animation_kinship_bridge.py path/to/bridge.json
```

The validator checks only bridge structure and ordering. Passing it does not make an ASCII specimen HEALTHY and does not promote sibling evidence to ASCII motion authority.
