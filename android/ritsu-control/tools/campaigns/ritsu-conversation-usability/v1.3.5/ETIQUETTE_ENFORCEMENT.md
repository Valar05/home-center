# Campaign Etiquette enforcement for Ritsu usability v1.3.5

Authority: live owner Campaign Etiquette document (read again 2026-10-29), repository AGENTS.md and AGENTS.base.md, current Ritsu Master, Ritsu Recovery Handoff and the Conversation Usability campaign ledger.

MANDATORY: one self-locating release and one invocation; never ask for an intermediate diagnostic ladder, never launch before verifying the immutable version/hash and source. Never override prior accepted source, dirty worktree, signing identity, pairing, journal or messages. Never restart an unverified Windows process. Remote recovery must query the ORIGINAL immutable turn and return a unique verified existing response or an explicit unresolved state, never retransmit the text.

Permitted remote lane: only existing Termux `cauldron` command string, with bounded transfer, exact hash readback, stored Windows receipt, guarded reversible patch and independent endpoint canaries. **Never** use Home Center, Computer Hands, new SSH or hidden ChatGPT APIs. GitHub repository writes require separate approval and are not attempted.

The Android build must use only the verified code24 staging source and accepted cert. Source staging, Gradle unit tests, native build, zipalign and signing happen inside one invocation; a failed build does not mutate Windows. The already-signed copy is published to `$HOME/storage/downloads`, SHA-verified and then `termux-media-scan "$PUBLIC_PATH"` must be invoked for that exact public artifact. Media scan requested is NOT Files app visibility. Failure to scan must not invalidate or delete a correctly copied APK.

The campaign NEVER opens/installs an APK through Termux. After real file publication, the OWNER alone selects the file in Android Files and approves installation. The user must not be asked to enter another command to discover basic progress, errors, paths or SHA evidence. Preserve stable run receipts. No background promises, fabricated physical tests, unverified replies, or automatic retry of ambiguous turns.
