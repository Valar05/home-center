# Campaign Etiquette read gate for Ritsu v1.3.3

Authoritative live document: https://docs.google.com/document/d/1wntegQjw7238dmGqbvs9TQmlsp4uXdXw7_wPciNx6sI/edit
Also read: Ritsu Master, Ritsu Usability Campaign, Ritsu Recovery Handoff and repository AGENTS.md/AGENTS.base.md.

Retained obligations: same immutable campaign ID and new versioned filename; one launcher; exact signer and input provenance; private isolated source; no assumed working directory; preserve dirty repo and existing app; no Home Center, Computer Hands or new network lane; Windows command strings via existing Termux cauldron ONLY; GitHub read allowed but writes not separately authorized; no app auto-install, pairing/key reset, journal rewrite, or automatic repost of ambiguous existing user turns; complete redacted inline receipts and rollback on Windows restart failure; production evidence not equal to host simulations; no manual diagnostic ladder; never treat a media scan request as proof of visibility.

**Mandatory public delivery hook:** after atomic file publication and SHA256 readback, call `termux-media-scan "$PUBLIC_PATH"` once on the exact final shared file, with bounded timeout and separate `COPY_VERIFIED` vs `MEDIA_REFRESH` outcomes. Never recursively scan thousands of unrelated files during one APK release. Missing Termux:API should not destroy a valid published APK. The owner installs through Android Files/Downloads and must never be forced into `termux-open`, `am start`, `pm install` or Android installer triggers from Termux.

**Original turn safety:** browser inspection is read-only; only immutable original turn ID/tab/digest and uniquely verified visible reply may be appended as a new completed journal event. A journal entry is never rewritten. If the reply is not uniquely present in accessible Chromium, refuse to infer it from unrelated ChatGPT sessions and never auto-retry. A missing linked-server receipt is NOT sufficient to prove a prompt was never sent elsewhere.

**Server rollback:** pin active Node source, commandline, listener IP/port and exact source anchors before replacing. Preserve private old source; test Node syntax; require authenticated read-only endpoint proof. On restart failure, restore old source and try to restore old service. A transport acknowledgement is not a proof of recovered reply.
