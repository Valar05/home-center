# ASCII Kinesis Skill

## Purpose

Use this skill for commissions that ask for ASCII art or ASCII animation as a durable motion artifact, especially when Drew references ASCII Kinesis, Vector Noodle, Embodied Kinesis, Pose Lab, contact sheets, Motion Dungeon, or the experiment anthology.

This skill is cumulative with `skills/fortress-core/SKILL.md` and the UAPL contracts in `docs/UAPL_ASCII_POSE_LANGUAGE.md` and `docs/UAPL_MOTION_SPA.md`.

## Commission meaning

In this context, "make ASCII art" does NOT mean paste a code block into chat and does NOT mean produce a research memo in Drive.

The commissioned delivery surface is a **new repository-backed, user-openable single-page application example** under the ASCII Kinesis anthology. Research, source mining, Drive notes, timing analysis, and GitHub issue receipts are supporting evidence only.

A worker has not completed a pass until the requested example exists in the repository and survives repository readback.

## Swarm deliverable contract v2 — hard lock

Every new ASCII Kinesis swarm example created under this contract MUST be a self-contained SPA with **exactly three primary tabs, in this order**:

1. **ASCII** — the full contact sheet as literal selectable/copyable text. It MUST NOT be an image, canvas-only representation, screenshot, SVG outline, rasterized font, or inaccessible visual substitute. Use a real `<pre>`/text surface with ligatures disabled and whitespace preserved. Formatting must remain aligned on desktop and mobile; horizontal scrolling is acceptable, character drift is not.
2. **JSON** — the structured motion/timing/provenance payload required to reconstruct and audit the example. This is the machine-facing tab and may contain the boring material: rig/joint schema, key IDs, timing classes, provenance, source identity, rights boundary, observation/inference split, compatibility data, and manifest/receipt fields.
3. **VIDEO** — an actual compiled motion video generated by the Motion Dungeon method from the abstract ASCII rig and timing data only. A research artifact, static contact sheet, or omitted-media note is not a substitute.

No fourth primary tab is permitted for v2 swarm examples. UAPL/UAT/source/manifest material remains durable but is folded into the JSON payload and/or repository files rather than gaining another primary SPA tab.

### Backward compatibility

This v2 contract is additive. Existing anthology v1 examples and previously delivered UAPL Motion SPA artifacts remain valid forever and do not need destructive rewrites.

Future readers/builders MUST continue to open v1 artifacts and MUST continue to open v2 three-tab artifacts. Later repository mutations may add internal fields, adapters, helper files, codecs, renderers, or metadata, but may not invalidate the v2 three-tab read path or silently reinterpret old timing/source fields.

## Motion Dungeon method for ASCII Kinesis

Motion Dungeon is a production method here, not permission to import expressive source art.

For a v2 swarm example:

1. Select/author decisive abstract ASCII rig keys from the extracted motion principles.
2. Treat those authored keys as semantic authority.
3. Assign explicit timing to every decisive key.
4. Use deterministic connective motion only to travel between authored keys. Interpolation may not invent a new contact, support state, limb meaning, weapon relation, root decision, or causal event.
5. Render frames solely from the abstract ASCII rig/text representation and its structured motion data. Do not render or embed source sprites.
6. Compile a real MP4 by default (`.gif` may additionally exist but does not replace the required video unless Drew explicitly changes the contract).
7. Embed or otherwise package that compiled video in the self-contained SPA so the VIDEO tab works without network access.
8. Preserve hashes/receipts sufficient to prove the video corresponds to the committed structured source.

Strong keys carry the performance. Holds must remain readable. Transitions exist to connect keys, not to do the acting. Unsupported states fail closed rather than being silently invented.

## Sprite-sheet mining law

When the commission is a Spriters Resource mining pass:

- select ONE ENTIRE sprite sheet from The Spriters Resource;
- inspect the whole sheet as evidence rather than cherry-picking one glamorous frame;
- do not use Drew's own animation work as source material;
- do not reproduce, trace, redistribute, or closely imitate copyrighted sprite art;
- preserve only general animation principles and source/provenance facts;
- the resulting repo example MUST use an abstract ASCII rig whose expressive appearance is independently authored and copyright-safe;
- a Drive research document or issue comment without a new repository SPA is `SUPPORTING_EVIDENCE_ONLY`, never completion.

## Timing contract

Every decisive key MUST record timing provenance.

- **OBSERVED** — timing or exposure is actually established from source evidence.
- **INFERRED** — source timing is unavailable; compile using PoseLab V1 Street Fighter timing vocabulary.

Required vocabulary:

- **ONES** = a new drawing/key sample every display frame.
- **TWOS** = one drawing/key held for two display frames.
- **FOURS** = one drawing/key held for four display frames.
- At nominal 24 fps: ONES≈24 samples/s, TWOS≈12, FOURS≈6.
- User shorthand `1s/2s/4s` means ONES/TWOS/FOURS, never seconds.
- **STREET_FIGHTER/CAPCOM** = nonuniform authored gameplay timing: anticipation holds, fast transitions, strong silhouettes, contact/impact emphasis, recoil/recovery holds, and selective exaggeration. Never claim inferred durations are source-authentic.

Minimum decisive-key data remains:

`{key_id, pose_rig, support_contact, motion_arc_root_note, timing_class, timing_provenance, causal_role}`

## Repository anthology rule

Each experiment gets its own durable directory:

`experiments/ascii-kinesis/<entry>/`

Do not turn a new experiment into a rewrite of an old specimen.

Generalized learnings belong in `docs/ASCII_KINESIS_GENERALIZED_LEARNINGS.md` and must cite supporting experiment IDs. One attractive specimen is evidence for a candidate learning, not automatic doctrine.

A v2 swarm entry should durably contain, directly or through deterministic reconstruction:

- raw literal ASCII contact sheet;
- structured JSON motion/timing/provenance data;
- source UAPL/UAT where applicable;
- compiled MP4 produced from the ASCII rig;
- deterministic builder/reconstruction source;
- manifest/receipt;
- the self-contained three-tab `*.motion.html` delivery artifact or a deterministic repository builder that regenerates the exact envelope.

## Source-before-presentation law

The raw ASCII/pose source is authoritative. Contact sheet and video may reveal or interpolate that source but may not silently invent motion semantics.

If a source video or embodied observation is private/user-supplied, persist the derived experiment and provenance boundary, not the raw private video, unless the user explicitly commissions source-video persistence.

## Completion gate

DONE for a new v2 ASCII Kinesis swarm pass requires ALL of the following:

- ONE new example exists under `experiments/ascii-kinesis/<entry>/`;
- its SPA has exactly `ASCII | JSON | VIDEO` primary tabs in that order;
- ASCII is literal selectable copyable text and alignment is preserved;
- JSON contains the structured rig, timing, provenance, source/rights boundary, compatibility data, and reconstruction facts;
- VIDEO is real compiled motion generated from the abstract ASCII rig/timing only via the Motion Dungeon method;
- every decisive key has timing class and provenance;
- reconstruction/build source and manifest/receipt exist;
- repository readback proves the durable entry exists;
- the relevant campaign/issue receipt points to the repository example;
- old anthology artifacts remain readable;
- human acceptance remains distinct from machine completion.

A Drive document, a timing study, an issue comment, a static image, a generated-but-unpersisted file, or chat prose cannot satisfy this gate.

## Swarm-manager rule

The animation swarm manager owns output shape, uniqueness, sequencing, compatibility, and correction propagation across workers. Workers own their assigned motion lanes, but they do not get to redefine completion.

When the manager says restart from the beginning, existing historical research remains evidence but does not count as the restarted deliverable series. Restarted workers create fresh v2 repo examples from Example 001 onward under an explicit restart namespace/sequence so historical specimens are not overwritten.
