## Source theory
Derived from the prior `PUNCH_CARD_APHORISM_THEORY.md` formulation: a compact phrase qualifies only when it can retrieve a larger model, reconstruct causal relations, execute into a decision/artifact, transfer beyond its first example, and remain correctable.

## Core law

**A PUNCH LINE ENDS. A PUNCH CARD EXECUTES.**

A phrase is not a punch-card aphorism because it is catchy. It becomes one only when it preserves enough causal structure to run.

For gameplay/system work, the minimum executable shape is:

**STATE + INPUT + RULE → NEXT STATE + OBSERVABLE CONSEQUENCE**

If the same state and input under the same rule can produce different next states, the source of variation must be named as an explicit input or deterministic seed. Hidden randomness is a failed card.

## Five punch-card gates
A candidate card must pass all five:

1. **Retrieval** — does the phrase reliably summon the larger model?
2. **Reconstruction** — can the relevant entities/relations be recovered from it?
3. **Execution** — can it produce a concrete inference, state transition, decision, or artifact?
4. **Transfer** — can the same relation survive a second domain or second gameplay situation without relying on surface resemblance?
5. **Correction** — can the card name its scope, provenance, counterexample, or failure boundary?

Deterministic classification:

- all five pass → `PUNCH_CARD_READY`;
- retrieval/reconstruction pass but execution fails → `MNEMONIC_ONLY`;
- phrase creates attitude but no reconstructable model → `SLOGAN_ONLY`;
- execution exists but correction is blocked/forbidden → `DOGMA_RISK`;
- gameplay state transition is underspecified → `GAMEPLAY_LOGIC_INCOMPLETE`;
- hidden randomness changes outcome → `NONDETERMINISTIC_RANDOMNESS`.

## Gameplay compilation
For gameplay judgment, compile before praising.

Required fields:

- **STATE** — the smallest state variables that matter before the action;
- **INPUT** — player action, event, collision, timer, command, or other explicit input;
- **RULE** — the deterministic relation that maps state/input to change;
- **NEXT STATE** — what state becomes true afterward;
- **OBSERVABLE** — what the player can see/hear/feel/read that proves the rule fired;
- **FAILURE / CORRECTION** — where the rule stops applying or what counterexample changes it.

If any required field is missing, do not call the mechanic "done" merely because the aphorism sounds right.

## Judgment examples

### `Not the floor`
Bad use: callback joke.

Executable use:
- STATE: worker is carrying infrastructure load personally;
- INPUT: system assigns another load-bearing duty to the same actor;
- RULE: if the actor has become the single structural dependency, stop assignment and create redundancy;
- NEXT STATE: work pauses or reroutes; backup ownership becomes required;
- OBSERVABLE: actor is removed from permanent load-bearing duty and the system records a stop-work/redundancy requirement;
- CORRECTION: temporary emergency support is not automatically structural capture.

That executes. It is a card.

### `It is too early to waste the fuck`
This is not automatically gameplay logic. It becomes a punch card only if used to drive a system.

Possible system compilation:
- STATE: limited attention/resource budget remains;
- INPUT: low-priority event requests commitment;
- RULE: reject or defer events below the current priority threshold;
- NEXT STATE: budget remains available for higher-value events;
- OBSERVABLE: deferred queue grows while critical path remains funded;
- CORRECTION: a low-priority event may cross threshold if its consequence changes.

## Anti-failure
Reject these failures:

- answering `punch me` with explanation instead of one line;
- omitting `fuck` from a punch request without an explicit waiver;
- making `fuck` decorative rather than semantically load-bearing;
- confusing abruptness with illegibility;
- mechanically spraying profanity or medical caricature to fake tic-like timing;
- quoting the aphorism theory without changing a gameplay decision;
- calling a callback an executable card;
- praising compression without reconstructing the rule;
- hiding state in prose that an implementer could not enumerate;
- using "emergence" to excuse unspecified randomness;
- adding randomness without treating the random draw/seed as an input;
- forcing every memorable phrase into gameplay logic;
- inventing a phrase after implementation and pretending it caused the design.
