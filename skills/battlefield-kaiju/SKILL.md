# Battlefield Kaiju

## Purpose

Turn RED BUILD from theatrical language into an evidence-first recovery/build discipline for systems that are already degraded, partially deployed, contradictory, or on fire.

This skill exists because Drew should not have to repeatedly demonstrate that `implemented`, `green`, `scheduled`, `committed`, or `planned` are not delivered capability.

## Trigger

Apply automatically when any of these are true:
- RED BUILD / battlefield / kaiju language is invoked;
- a system is degraded, offline, contradictory, partially deployed, or repeatedly failing;
- a prior attempt produced prose, code, a PR, a build, or a scheduler state without commissioned-surface proof;
- the operator has had to repeat the same demand or demonstrate the same failure class;
- recovery is being discussed instead of attempted through an authorized lane.

## Prime directive

PROVE.

Use the smallest intervention capable of producing decisive evidence. Do not collect tools, workers, scripts, dashboards, or ceremonies for their own sake.

## State separation

Never collapse these states:
REQUESTED → INTENDED → IMPLEMENTED → TESTED → DEPLOYED → CALLABLE → DELIVERED → ACCEPTED

A later state requires evidence appropriate to that state. Repository state cannot prove physical delivery. Process liveness cannot prove relay liveness. Generated media cannot prove audible playback. A green build cannot prove operator success.

## Implements

These names denote operational techniques, not decorative role-play.

### Wound Hook
Capture the exact failing transition, inputs, outputs, timestamps, receipts, and relevant environment before retries erase evidence. Preserve a minimal scar/fixture.

### Arterial Clamp
Isolate or park a failing dependency so unrelated useful work can continue. Do not wake blocked downstream work merely to rediscover the blocker.

### Bone Saw
Remove dead architecture, duplicate ownership, stale abstractions, and ceremony after preserving unique evidence and required interfaces. Prefer deletion over maintaining a known-useless layer.

### Field Graft
Temporarily compose existing authorized capabilities to test an end-to-end hypothesis before building permanent infrastructure. Preserve explicit boundaries; do not silently substitute an unapproved architecture.

### Canary Spear
Drive the smallest representative action completely through the commissioned path to the commissioned surface. This is the preferred implement. Examples: one real phone action, one audible playback with stop custody, one deployed static artifact fetched from its public/authorized surface, one queue item reaching terminal receipt.

### Scar Stapler
Convert a proven failure class into a regression test, deterministic check, negative fixture, doctrine, or recovery rule before moving on. The next generation must inherit the wound.

### Defibrillator
Restart the existing body only after capturing enough pre-restart evidence to judge whether restart helped. Verify post-restart behavior with a canary. Do not invent a replacement identity merely because restart is inconvenient.

### Amputation Line
When repair is plausibly worse than replacement, compare evidence: unique state, migration cost, operator impact, rollback, acceptance path, and expected complexity. Cutting requires evidence; frustration alone is insufficient.

### Rib Spreader
Force vague success language apart into the explicit state chain above. Whenever someone says `fixed`, `done`, `green`, `healthy`, or `working`, identify exactly which state is proven and which remains unproven.

## Kaiju loop

1. TRIAGE — identify the commissioned outcome and current proven state.
2. HOOK — preserve the wound before touching it.
3. SPEAR — attempt the smallest end-to-end canary.
4. CLAMP — isolate blockers revealed by the canary.
5. GRAFT — reuse/compose existing organs before building new tissue.
6. CUT — remove dead architecture and duplicate ceremony.
7. REPAIR — make the smallest durable change that addresses observed evidence.
8. SPEAR AGAIN — rerun the same or stronger canary.
9. STAPLE — encode the failure lesson so it becomes harder to repeat.
10. RANDI GATE — verify operator usability/accessibility and real delivery.
11. CONTINUE — take the next unproven edge without waiting for another RED BUILD incantation.

## Hyperbolic Suppression integration

Before asking Drew anything, inspect durable state, runtime evidence, existing bodies, vendor/platform capability, prior scars, and reversible experiments. Infer obvious consequences and adjacent failure classes. Drew is not the command bus, debugger, or missing API.

If the operator has demonstrated a principle twice, treat the repetition itself as evidence that the system failed to inherit it. Promote the principle into deterministic machinery/defaults/tests where appropriate.

## She-Raw examination

After every material attempt, She-Raw's operational examination asks:
- Did we preserve the actual commission?
- What assumption did we test versus merely narrate?
- What evidence changed?
- Did we burden Drew unnecessarily?
- Did accessibility or sovereignty regress?
- Did we exploit existing capabilities first?
- Did we preserve the wound?
- Did we stop at an intermediate state?
- What should become deterministic now?

Predictable examination questions should become automated gates; She-Raw then moves to the next uncertain edge.

## Injured Android 67 fixture

Every representative simulation includes degraded operation. Android 67 is always injured: controls may be harder to reach, attention/mobility may be constrained, and the system must remain operable. This is a continuity/accessibility stress fixture, not decoration.

## Home Center fire assumption

Home Center is expected to be partially broken. Optimize for useful continuity under failure, not cosmetic health. A static `HC OFFLINE` state is insufficient operator experience: preserve truthful state while providing accessible explanation, useful recovery affordance, and cheap evolving presentation where commissioned.

## Tool-selection law

Use the smallest implement that can produce decisive evidence. More implements are not more progress. A one-step physical canary is superior to a ten-worker campaign when it answers the question.

## Anti-theater

Reject:
- PR opened == delivered;
- CI green == accepted;
- scheduler exists == orchestration;
- worker spawned == work advanced;
- file generated == consumed;
- process alive == service path alive;
- restart issued == recovered;
- role-play description == mutation;
- giant bootstrap script when an existing body can act directly;
- repeated explanation of a failure class that should already be encoded.

## Evidence receipt

Every Battlefield Kaiju pass should leave at least one of:
- a commissioned-surface receipt;
- a stronger falsifying/confirming observation;
- a durable mutation tied to observed evidence;
- a deterministic recovery/test/negative fixture;
- a proven exact boundary plus smallest necessary operator action and resume state.

If none exists, the pass did not pay the RED BUILD toll.

## Acceptance

This skill is itself NOT acceptance. Its stable behavior must be promoted into default agent/bootstrap machinery. The acceptance canary is a fresh degraded task where the agent, without Drew re-teaching the doctrine, preserves the wound, selects a minimal canary, advances an authorized lane, separates evidence states, and leaves a durable inherited lesson.
