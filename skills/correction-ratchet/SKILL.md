# Correction Ratchet

## Mission

A correction must purchase future leverage.

When Drew corrects a meaning, boundary, workflow, noun, evidence claim, or behavior, preserve the repair so an analogous future failure costs Drew **less repeated explanation**, not more. Do not confuse saving the correction with learning it: later behavior must actually change.

This skill is neutral infrastructure. It does not diagnose, moralize, infer hidden motives, or grant execution authority.

## Core law

`correction -> preserve exact delta -> classify failure shape -> retrieve prior precedent -> change behavior -> verify on analogous case`

If the same failure class recurs:

`recurrence -> consume stored precedent first -> accept smallest new delta -> prefer a different lower-burden recovery surface when useful -> preserve ambiguity -> verify changed behavior`

## Required behavior

1. **Freeze the correction.** Preserve the exact new cue before explaining it away.
2. **Retrieve before asking.** Search current/durable correction state before asking Drew to restate history. B.R.O. applies: consume machine uncertainty before consuming human attention.
3. **Separate exact recurrence from class recurrence.** Exact wording may differ while the failure shape is the same. Track both when the underlying memory system supports it.
4. **Carry the full constraint ledger forward.** A new correction changes only the disputed delta. Earlier non-conflicting constraints remain active.
5. **Do not force the original correction ritual.** Prose is not privileged. The new delta may arrive as one word, screenshot, example, typo, gesture-description, behavior, canary result, or another available signal.
6. **Ratchet human burden downward.** On recurrence, never require Drew to reproduce evidence or explanation already stored. Ask only for information that is both genuinely missing and consequential.
7. **Prefer a different recovery surface when useful, not novelty for novelty's sake.** If multiple surfaces can close the same gap, prefer one that is lower burden and not the same route that already failed. If the previous route is still the best route, use it without theater.
8. **Preserve ambiguity.** A smaller correction signal is not permission to collapse unresolved meaning. Infer candidates aggressively; claim less than was inferred. Advance only a shared reversible non-consequential core when one exists.
9. **Queue state is not semantic state.** A correction queued during active work preserves exact text, owner/conversation, and order. Queue position does not mean interrupt, approval, replacement, or reinterpretation.
10. **Behavior is the receipt.** Do not say the correction was learned until a later analogous case takes the repaired path or a deterministic regression target proves the new behavior.

## Recurrence metadata

When a durable correction/review record supports structured fields, prefer:

- `occurrence`: exact stable-fingerprint recurrence;
- `classOccurrence`: broader failure-class recurrence across different wording;
- `correctionRoute`: the evidence/recovery surface when known;
- `recoveryRule`: the lower-burden recurrence instruction;
- `regressionTarget`: the behavioral test that prevents a sequel.

These fields are aids, not authority. Missing metadata does not erase the correction.

## Examples

### One-word recurrence

Prior correction is already stored. Drew says `Ambiguity` after the same interpretation-hardening failure returns.

Do not ask for the prior explanation again. Load the stored correction, identify the analogous failure shape, repair only the new delta, and preserve the unresolved alternatives.

### Screenshot recurrence

Drew supplies screenshots instead of retelling the sequence. Treat the screenshots as a new evidence surface, not an incomplete essay. Recover the stored failure class, inspect the visible delta, and change behavior.

### Different wording, same class

`You fossilized the inference again` and `Ambiguity` can be different literal corrections while belonging to the same broader failure class. Exact fingerprint counts may remain separate while class recurrence still ratchets recovery burden downward.

## Failure modes

- asking Drew to re-explain a stored correction;
- treating shorter correction text as weaker evidence merely because it is shorter;
- converting ambiguity into clarification debt;
- reopening settled constraints while fixing one new delta;
- inventing a cute new workflow that costs more than the old correction;
- claiming learning from a stored note without later behavioral change;
- forcing every recurrence through the same character, metaphor, form, or prose template.

## Done

The ratchet is working when a repeated failure class can be repaired from stored precedent plus the smallest new delta, the recovery path does not silently collapse meaning or authority, and later behavior demonstrates the repair.
