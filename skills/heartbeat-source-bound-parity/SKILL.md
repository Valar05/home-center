# Heartbeat Source Bound Parity

Use this skill when heartbeat light records can enter through more than one source path, especially canonical JSON parsing and direct `HeartbeatSkillPolicy.Candidate` construction.

## Contract

A display-ready direct-source candidate MUST satisfy the same post-trim Java `String.length()` field limits as `HeartbeatEnvelopeParser`. The parser's public candidate-field constants are the single bound authority; do not copy their numeric values into a second table.

This is a source/evidence safety rule, not merely a speech rule. TalkBack projections intentionally use smaller Unicode-code-point budgets, but those projection limits do not protect scene hashing, checkpoint identity, native semantic ownership, touch detail, or memory from an oversized source record.

Human-facing semantic text remains Unicode subject to the existing semantic-safety rules. Machine semantic IDs remain subject to the deterministic ASCII owner-token boundary. Bounds do not authorize normalization, truncation, or rewriting of canonical source identity: an oversized typed record is rejected from display-ready state.

## Fail-closed composition

When an oversized direct material candidate reaches `HeartbeatSceneGraph.build(...)`, display-ready selection must reject it. If a last-good frame exists, preserve that contact, keep the attempted pulse as diagnostic identity when safe, expose the existing typed-contract rejection boundary, and clamp both frame and node transition motion.

Do not synthesize a smaller replacement record. Do not truncate evidence into something that can pass the typed gate. Speech projection may be bounded independently only after source acceptance.

## Regression requirements

Keep source fixtures for:

- one direct typed candidate exactly at every parser-governed variable field bound;
- each variable field exceeding its parser bound by one;
- direct-source rejection preserving last-good contact and forbidding transition motion.

These fixtures are regression source until they actually execute. Never report their existence as `TESTED`.

## Capability membrane

Keep these states separate: requested, implemented source, exact repository readback, regression source, tested, runtime consumed, UI rendered, TalkBack exercised, deployed, callable, executed, delivered, accepted.

This skill owns no renderer, overlay controller, transport, phone execution surface, recovery daemon, or P0 coordination. Compose existing organs only.
