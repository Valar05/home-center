# Heartbeat Native Motion

## Purpose
Turn semantic heartbeat transition truth into one bounded native visual consequence without allowing polling, evidence refresh, cold-start history, visibility restore, or taste to manufacture Christmas blinking.

This skill is source doctrine for the existing Operator Overlay. It does not own a renderer, controller, phone lane, P0 recovery path, or deployment authority.

## Canonical inputs
Consume the already-accepted `HeartbeatSceneGraph.Frame` / `HeartbeatOverlayViewModel.Model` only. Do not infer motion from timestamps, poll frequency, labels, colors, raw payload arrival, or reviewer enthusiasm.

A node may receive one native cue only when all of these are true:

- `node.transitionMotion == true`;
- `frame.transitionMotionAllowed == true`;
- the heartbeat/details surface is actually presented;
- platform animators are enabled;
- the existing owner has an established prior semantic announcement identity and observes a new transition identity.

If any gate is false, motion is blocked. Revealing a surface later must not replay a transition first observed while hidden/collapsed. Exact retry and evidence/provenance-only refresh earn no motion. The first persisted frame seen after owner startup may render, but it is history without an observed baseline and therefore does not earn a cue merely for existing.

## Existing-owner source wiring
`OperatorOverlayService` is the sole native owner and now consumes the policy in source:

- actual presentation is `overlayVisible && heartbeatSurfaceVisible`;
- platform animator permission comes from `ValueAnimator.areAnimatorsEnabled()`;
- the existing announcement identity supplies the established-history transition gate, without coupling motion to mute;
- transitioning existing Buttons consume `Model.motionDecisionFor(...)`;
- the existing heartbeat summary consumes `Model.summaryMotionDecision(...)` only for pure removal;
- hidden/collapsed or animator-disabled presentation cancels any stale heartbeat view-property animation and resets alpha/scale to resting values;
- hiding, collapsing, and owner destruction also reset the bounded cue state.

This is source wiring only. It does not prove Android displayed the cue, that a device honored reduced-motion behavior exactly as intended, or that a phone received/deployed the source.

## Pure-removal rule
A material removal changes frame structure but the removed node no longer exists. Do not invent a replacement light merely to animate it.

When `frame.transitionMotionAllowed == true` and no surviving/added node owns `transitionMotion`, the existing heartbeat summary is the only honest fallback surface for one bounded cue. Additions and state/consequence changes already have a node owner and must not double-pulse the summary.

## Accessibility and reduced motion
Motion is supplementary only. State remains available through non-color tokens, text, touch detail, and TalkBack semantics.

- platform animation disablement is authoritative;
- no autoplay loop;
- no repeating blink;
- no motion required to understand state;
- no speech is generated by this skill;
- motion does not change selection, keyboard focus, TalkBack focus, operator authority, or execution state.

The current pure policy uses a short one-shot cue contract (`140ms`, start scale `0.96`, start alpha `0.72`). The existing owner applies those values through the native view property animator and settles the view back to alpha/scale `1`. Those facts prove source wiring, not runtime observation.

## Existing organs
- semantic truth: `HeartbeatSceneGraph`
- transition/presentation history: `HeartbeatOverlayRefreshPlan`
- UI-ready projection: `HeartbeatOverlayViewModel`
- pure decision policy: `HeartbeatNativeMotionPolicy`
- native owner: existing `OperatorOverlayService`
- source teaching organism: `docs/try-forever/heartbeat-motion-clamp-source-specimen.html`

Do not create a neighboring animator service/controller. The existing owner is the only authorized Android consumer.

## Regression doctrine
Regression source must cover at least:

- material node transition allowed under all gates;
- collapsed/hidden presentation blocks node and summary motion;
- platform-disabled animators block node and summary motion;
- evidence-only refresh earns no cue;
- pure removal uses only the existing summary fallback;
- an existing node owner suppresses summary double-pulse;
- cold start has no established transition baseline and does not autoplay persisted history;
- interrupted last-good contact cannot leak prior motion.

Regression files remain regression source until an authorized runner actually executes them.
