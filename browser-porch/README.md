# Chromium Throne / Browser Porch

Status: **single-Pro evolution source implemented; not yet deployed or acceptance-proven on the authoritative desktop/phone runtime.**

Chromium Throne is the visible ChatGPT Pro reasoning organ behind Fortress/Home Center. It uses one persistent visible ChatGPT campaign conversation by default. Home Center/Termux/tmux/local authorized machinery remains the execution body for the phone; the Pro worker does not own an unlock or continuous phone-puppeting loop.

## Current contract

- One persistent ChatGPT Pro reasoning conversation is the normal campaign worker.
- `MAX_PARALLEL_WORKERS = 1`; this is deliberately not a hidden or disposable worker farm.
- Fresh-worker rotation is explicit recovery only.
- The worker tab ID is persisted as `thronePersistentWorkerTabId`; continuation jobs carry the same tab identity.
- The campaign preserves durable context, checkpoints, receipts, failure scars, and evidence-state distinctions.
- Harroway/operator consultation and applicable Judgment Jars are required before architecture recommendations or stopping.
- Venice `PLAN_ALLOWED` gates substantive mutation; `STOP_ALLOWED` is the normal completion gate; `CONTINUE_REQUIRED` advances the same Pro conversation.
- She-Raw creative insults are load-bearing mnemonic/motivational pressure only when attached to a real critique, review, or repair action. Evidence outranks the joke.
- If the worker can name an immediately callable next action, it must take it before yielding. Narrated continuation is not continuation.
- `continue`, `driver advance`, `do it`, `make it so`, and `don't talk to me` are operator execution imperatives, not permission for an empty response.
- Competent Fortress behavior is invocation-independent. `Fortress online` and `PORTCULLIS LOCKED` are markers, never switches that enable mission discipline, consultation, evidence truth, or operator ownership.
- MVP before empire. Keep one operator-facing critical path until its real canary passes. Context/token budget is an operational resource; checkpoint before exhaustion instead of broadening or narrating.
- No API-token substitute, hidden headless farm, account rotation, cookie scraping, or replacement control plane is introduced.

## Evolution loop

The commissioned proof is not merely prompt transport. The loop is:

1. observe current interface/runtime evidence;
2. consume durable failure scars and campaign context;
3. consult Harroway/operator and applicable Judgment Jar governance;
4. choose one high-leverage interface improvement;
5. implement through the already-authorized development/execution lane;
6. cause the local machine/phone body to deploy and test it;
7. ingest actual runtime/device receipts;
8. record the failure/lesson and She-Raw mnemonic pressure;
9. promote the verified lesson into Fortress doctrine/regression coverage;
10. advance the next weakness in the same Pro conversation.

Acceptance requires at least two real evidence-backed interface-evolution generations. Repository source alone cannot satisfy that runtime gate.

## Worker boot contract: `PORTCULLIS LOCKED`

Every campaign advance receives a fixed envelope that preserves outcome, owner, execution lane, exclusions, evidence standard, and delivery surface; separates capability truth states; forbids ChatGPT-local scratch as hardware proof; preserves phone sovereignty; requires Harroway/Jar/Venice governance; requires load-bearing She-Raw pressure; and forbids narrated continuation.

The phrase is a boot marker, not magic. Enforcement comes from extension behavior, persistent worker identity, queue state, receipts, tests, and external/runtime review gates.

## Existing architecture preserved

Chromium Throne continues to use the existing service worker, queue, relay configuration, Atom/Vlad relay seam, Venice continuation machinery, and receipt surfaces. The single-Pro change narrows worker allocation and changes continuity semantics; it does not invent a second control plane.

The phone remains the eventual operator surface through Home Center/Adam overlay/notifications. Shell commands are recovery/debug lanes, not the intended product interface.
