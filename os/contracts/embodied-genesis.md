# EMBODIED GENESIS / IN-BODIED GENESIS

Status: ACCEPTED CANON / binding capability doctrine
Custody: Adam under TOUCHED IT -> OWN IT

## Canon names
- **Embodied Genesis** — primary canonical name.
- **In-Bodied Genesis** — accepted canonical alternate/descendant phrasing; preserve it rather than autocorrecting it away.
- **Bodily Genesis** — related phrase/shape and valid retrieval alias where context supports it, but does not supersede the two accepted names above.

## Core law
The system should derive, author, test, and improve embodied behavior from evidence and its existing bodies without requiring Drew to physically demonstrate when sufficient evidence already exists. Drew may demonstrate when useful or desired, but demonstration is a fallback/source contribution, not the default missing middleware.

Before asking Drew to demonstrate, the system must mine available embodiment evidence: existing video/reference performances, Embodied Kinesis/Motion Dungeon corpus, rig/model state, accepted key poses, animation fixtures, phone/device sensors where authorized, prior demonstrations, procedural motion grammar, accessible external references where commissioned, and existing deterministic movement primitives.

If evidence is sufficient, genesis proceeds without Drew. If evidence is insufficient, record the exact missing observable and request only the smallest demonstration that resolves it. A vague 'show me' is failure.

## Genesis loop
EVIDENCE -> OBSERVE -> EXTRACT DECISIVE STATES/CONSTRAINTS -> GENERATE EMBODIED CANDIDATE -> SIMULATE/ANIMATE -> COMPARE -> REGNET/QA -> TASTE/JUDGMENT -> PUNNETT KEEP/REJECT/MUTATE -> DEPLOY/RENDER -> RECEIPT -> LEARN.

Repeated successful embodied judgments compile downward into deterministic motion/pose/interaction grammar so future genesis needs less inference and less human demonstration.

## Relationship to Embodied Kinesis
Embodied Kinesis studies, authors, evaluates, and executes motion. Embodied Genesis is the generative/evolutionary faculty that creates new embodied behavior from mined evidence and inherited motion genes. They share evidence, rigs, key-state grammar, regression fixtures, and acceptance receipts; they are not neighboring architectures.

## Punnett
Every generated body/action preserves lineage: source evidence + inherited motion genes + mutation -> phenotype -> fitness -> KEEP/REJECT. User demonstrations, when provided, have high evidentiary weight but do not erase other valid evidence. Accepted motion traits become reusable genes; failures become negative fixtures.

## Operator law
Drew is not the default mocap rig, camera operator, pose oracle, or missing sensor. Existing authorized bodies and evidence are consumed first. If a human demonstration is genuinely required, explain exactly what cannot be inferred and what minimal movement/view is needed.

## Truth states
REQUESTED -> EVIDENCE_RECOVERED -> DEMONSTRATION_NOT_REQUIRED / DEMONSTRATION_REQUIRED_WITH_EXACT_GAP -> CANDIDATE_GENERATED -> COMPARED -> QA_PASSED -> TASTE_PASSED -> DEPLOYED/RENDERED -> PHYSICALLY_OR_PERCEPTUALLY_VERIFIED -> USER_KEPT.

Do not collapse states. This document canonizes the capability/doctrine; it does not claim a complete deployed Embodied Genesis runtime already exists.
