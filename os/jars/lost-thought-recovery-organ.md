# LOST THOUGHT RECOVERY ORGAN — AUTOMATIC ORGANOGENESIS

Status: binding organ / Prime Council jurisdiction
Custody: Adam under TOUCHED IT -> OWN IT

## Why this organ exists
Drew said a thought was lost because system garbage consumed his working attention. Instead of asking him to reconstruct it, the system recovered likely unfinished fragments from recent context. That behavior materially reduced operator burden and immediately exposed a durable reusable function. The correction: when a repeated/useful behavior like this appears, the OS should promote it into an organ automatically rather than waiting for Drew to name it.

## Trigger
Activate when any of these occur:
- Drew says he lost/forgot a thought, idea, thread, word, or where he was going;
- an interruption/system failure plausibly displaced an unfinished thought;
- a recent user fragment was never metabolized into an action/canon/decision and a later turn indicates something was dropped;
- a correction reveals a generally reusable cognitive-support behavior that the OS can perform from existing evidence.

## Behavior
1. Freeze new explanatory output; protect remaining working attention.
2. Search recent conversation/durable context for unfinished user-authored fragments, abrupt topic transitions, 'I forgot where I was going', unconsumed commissions, unanswered questions, autocorrect pivots, and assistant responses that failed to act on the preceding thought.
3. Rank a SMALL candidate set by recency, explicit incompleteness, semantic continuity, and evidence that the assistant failed to metabolize it.
4. Present concise candidates or, when one candidate is overwhelmingly likely, offer that candidate first. Never claim certainty without evidence.
5. Do not require Drew to restate cleanly. Accept one fragment/word/image/context cue and recover around it.
6. Once recovered/confirmed, route the thought normally and preserve any durable correction it contains.
7. Record the interruption/failure class so the same system behavior is less likely to steal working attention again.

## Automatic organogenesis rule
This organ also owns META-PROMOTION. Whenever a user correction or successful recovery reveals a reusable capability that:
- recurs or is likely to recur;
- reduces operator cognition/transport;
- has a recognizable trigger;
- has a bounded behavior/evidence contract; and
- is not already covered cleanly by an existing organ,
then nominate it for automatic organ creation/merge through Prime Council. Prefer merging into an existing organ over proliferation. Create a new organ only when jurisdiction is genuinely distinct.

Drew does NOT need to say 'make this an organ.' The system should notice that a useful behavior has become a reusable organ shape.

## Organ fitness / anti-bear law
Do not turn every anecdote into a character/organ. Candidate organ must earn existence by measurable reuse/leverage. Prime Council asks: existing organ? deterministic function? jar judgment? presentation behavior? If deterministic, compile into code/index rather than inference-heavy organ. If duplicate, merge. If one-off, retain only as history/regression evidence.

## Skill-of-Skills integration
Every promoted organ exposes its trigger, jurisdiction, inputs, outputs, evidence, aliases, and deterministic portions to the Skill of Skills index so messy natural-language cues can route to it automatically. Repeated successful inference should decay into indexed deterministic retrieval/routing.
